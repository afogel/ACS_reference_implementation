# Fixture: conformant

One session, `session-clean`, that breaches nothing: handshake first, a DENY with its `reasoning`, chain heads published and signature-covered, lineage within the session with monotone trust, an Intent extension that legitimately widens `Intent.parsed`, and matching entry hashes. An `agbom/snapshot` at seq 2 precedes the content-bearing hooks, `prov-user-input` (`user_input`) is `trusted` per §7.2, every ContextEntry carries §8.1's SHOULD fields (and `previous_hash` from the second entry on), each decision is logged with `reasoning`, `model_identifier` and `confidence`, and the Guardian advertises both ACS-Crypto algorithms. Both engines must derive an empty violation set, under every profile: the differential does not scope by profile, so the fixture has to satisfy the profile-scoped provisions too. It also cites ACS-REQ-0007, ACS-REQ-0010, ACS-REQ-0011, ACS-REQ-0013 and ACS-REQ-0017 as the provisions its clean run exercises most directly.

## Reading the facts files

Each `facts/<relation>.facts` starts with `#` comment lines that name the relation's columns and its source, copied from `ir/vocabulary/relations.yaml`; the tuples follow, one per line, tab-separated. The evaluator skips comment lines and Soufflé is run on a copy without them. Values are named for what they are: `session-…` for a session id, `entry-N` for a ContextEntry id, `prov-…` for a provenance id (`prov-user-input` came in as `user_input`, `prov-agent` is `agent_generated`), `hash-…` for an `entry_hash`, `head-N` for the chain head published at response `N`, `req-N` for the request id of seq `N`, and `fingerprint-…` for a canonical-form fingerprint. Response lines use seq numbers ten times their request's (request 2 is answered at 20).
