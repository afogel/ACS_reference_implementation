# V3: All five dispositions, and both failure postures

**Demo:** One bundle produces allow, deny, ask, and a rewritten tool call, plus a policy-fired allow that is AGT's `warn`. Then kill the Guardian mid-flight twice — once under `on_decision_failure: proceed`, where the step proceeds and an audit event appears; once under `deny`, where it blocks. Same adapter, same policy, posture negotiated at handshake.

**Master doc:** [`docs/shaping/acs-reference-impl-slices.md`](../../docs/shaping/acs-reference-impl-slices.md) §V3 — authoritative for this slice's scope.

**Affordances:** U23, N6, N7, N27, N51, S13, S14 — defined in [Detail C](../../docs/shaping/acs-reference-impl-shaping.md#detail-c-affordances).

## What this slice delivers

AGT's five verdicts — `allow`, `deny`, `escalate`, `transform`, `warn` — all arrive over the ACS wire as real decisions, driven from `data.agt.defaults.config` over the pinned, unforked stock bundle (R1.2). `mapping.yaml` is the single source of truth for the mapping: `allow`→`allow`, `deny`→`deny`, `escalate`→`ask`, `transform`→`modify` (carrying the rewritten argument, R1.6), and `warn`→`allow` **with non-empty `policy_references`** — the one thing distinguishing a policy-fired allow from a clean one. [`docs/demos/v3-runbook.md`](../../docs/demos/v3-runbook.md) walks through all five with the real captured output, plus both failure postures.

Two things had to exist before that claim could be tested live, and both are structural, not configuration:

- **`mapVerdict` synthesizes `modifications`** from an AGT `transform`, and **the adapter applies them** to produce the host's actual rewritten input (`applyModifications`, N7). V1 mapped `transform` → `modify` while emitting no `modifications` at all — invalid per §6 — and even carrying the object would have done nothing, since Claude Code's `updatedInput` doesn't accept ACS's `modifications` shape verbatim.
- **`applyFailurePosture` (N6)** resolves what happens when no decision arrives at all — Guardian silent, transport dead, an error with no decision — to the deployment's negotiated `on_decision_failure` posture, auditing every fail-open `proceed` (S14, §6.4's MUST). This is delivery failure, kept structurally separate from an AGT `deny` **verdict**, which is always honoured regardless of posture (R1.5) — conflating the two would either break that invariant or halt production on a network blip. **`N27 denyOnInvalidEnvelope()`** closes the other half: a Guardian-side failure (a schema mismatch, or evaluation itself throwing) now arrives as an honoured `deny` decision instead of a bare JSON-RPC error, so a fail-open posture can never let it through unnoticed.

**Getting `warn` live took an annotator, not a config value.** `input.annotations` never reaches policy input from the ACS snapshot — five placements were tried during planning and all were dropped. It arrives only from a manifest-declared annotator, dispatched through the SDK's own `annotatorDispatcher`. [`policy/manifest.drift.yaml`](../../policy/manifest.drift.yaml) is a **separate** manifest declaring exactly that; `policy/manifest.yaml` is untouched, so no existing behaviour changes and a deployment wanting no annotator has none. `createBridge` and `startGuardian` both grew a matching optional `annotator` option (`packages/agt-bridge/src/index.ts`, `packages/guardian/src/server.ts`).

**The stock approval gate is a single global switch, and that is a mechanic of this demo, not a shortcoming in AGT.** The priority chain is `deny > escalate > transform > warn > allow`, and the escalate gate is `cfg.approval.required` — a global boolean, not scoped to a rule. With approval on, every step that is not denied escalates, so `allow`/`transform`/`warn` are unreachable in that same config document. Covering all five verdicts therefore means five config documents over the one pinned bundle, not one. `test/helpers/config-bundle.ts` is the test-only helper that makes that practical: it copies `policy/lib/*.rego` into a fresh temp directory alongside a generated `data.json`, and asserts every copied file is byte-identical to its source on every build — a fixture bundle that silently forked the pinned bundle would quietly void this project's central claim while every test still passed. AGT's stock library is a starting default for hosts that author no Rego; a host wanting one deployment to both auto-allow and require approval writes a rule, which is exactly what the Rego surface is for.

**Corrected from the original demo sentence: ACS `defer` has no AGT verdict behind it, and that is ACS headroom, not a gap this slice needed to fill.** AGT's verdict vocabulary is exactly five, and none of them maps to ACS `defer` — `mapping.yaml` correctly declares no rule producing one. The only conformant route to a `defer` is ACS §9.2's approver-incapable substitution, which the spec deliberately keeps off the wire in v0.1 ("part of the Guardian's policy bundle," not a wire-level declaration) — so it is driven by no AGT verdict at all. Manufacturing one here would invert R1's claim, which runs one direction: AGT is completely expressible in ACS. ACS carrying a disposition AGT has no need for is exactly the wider-contract finding this slice makes, not something to paper over. What this slice actually demonstrates is AGT's five verdicts arriving losslessly over the wire — R1.2 moving from unit-tested to live.

## What is explicitly not in this slice

- **A drift score derived from the ACS envelope.** The `steps/toolCallRequest` payload carries `tool`, `operation`, `capability`, `arguments`, `raw_command`, `intent` — nothing a drift score could honestly be derived from. AGT's own specification puts behaviour-drift detection *outside* the policy engine by design ("Hosts run a behaviour-drift detector outside the policy engine"), so a host-supplied score (this demo's stub annotator, standing in for a real detector) is AGT working as intended. This is a note about ACS v0.1.0's wire coverage, not about AGT — recorded here for V7's conformance matrix, not as a limitation of this slice.
- **Real negotiation of the failure posture, or of anything else at handshake.** The posture is declared by the Guardian (`ACS_ON_DECISION_FAILURE`) and read by the host; nothing about the exchange picks a mutually agreeable value. Same as V1's `negotiated_version`/`selected_transport` — a fixed declaration on both ends, not the negotiation the field names imply.
- **Session state and provenance carriage** (SessionContext lineage, `result_labels` round-tripping through `input.ifc.source_labels`) — that is V6.
